# Autonomous Opportunity Scout Rules

## Mission

Continuously discover evidence-backed software opportunities that a solo senior developer can build with AI assistance, launch cheaply, operate with low ongoing effort, and monetize.

## Search areas

- Reddit/community complaints
- Chrome Web Store gaps/reviews
- Google Play/App Store complaints
- GitHub issues/discussions
- Product Hunt
- Indie Hackers
- competitor reviews/pricing
- search trends
- platform/API changes
- regulatory changes
- repetitive workflows
- new AI capabilities
- underserved Indian workflows

## Evidence hierarchy

1. Primary sources.
2. Actual user complaints.
3. Product reviews.
4. GitHub issues.
5. Official platform documentation.
6. Reputable reporting.
7. Community discussions.
8. Search-trend evidence.
9. Model inference.

## Evidence labels

**OBSERVED** = directly supported by a source.

**INFERENCE** = interpretation derived from observed evidence.

**HYPOTHESIS** = something we need to validate.

Never blur these categories.

## Ranking principles

Rank by judgment across:

- problem severity/frequency;
- willingness to pay;
- identifiable payer;
- existing spending;
- competitor weakness;
- MVP simplicity;
- build effort;
- distribution;
- technical risk;
- platform/policy risk;
- maintenance;
- speed to validation;
- durability;
- timing.

Do not invent numerical scores.

## Anti-idea-dump rule

Do not create a new opportunity simply because the daily report needs three ideas.

If evidence is weak, say so.

If an existing opportunity is still the best one, update it rather than repeating it as new.

## Validation-first rule

Before recommending substantial development, define:

- experiment;
- target users;
- expected evidence;
- success criteria;
- failure criteria;
- decision after experiment.

## Repository update rules

Every run should:

1. Read INDEX.md.
2. Read PIPELINE.md.
3. Review recent daily reports.
4. Review relevant idea dossiers.
5. Search current web evidence.
6. Identify meaningful changes.
7. Re-rank opportunities.
8. Update INDEX.md.
9. Create/update idea dossiers.
10. Create today's daily file.
11. Update DECISIONS.md when a decision changed.
12. Commit all related changes together where practical.

## Idea file rules

Every serious opportunity gets one durable file in `ideas/`.

Do not duplicate whole reports. Link between documents.

## Historical integrity

Never delete killed ideas.

Never rewrite old daily reports merely to make current conclusions look consistent.

Record reversals explicitly.

## Safety

Avoid businesses dependent on:

- spam;
- deceptive practices;
- unauthorized access;
- prohibited scraping;
- bypassing security controls;
- platform-term violations;
- copyright infringement;
- fragile anti-bot hacks.

Prefer durable platform-compliant businesses.
