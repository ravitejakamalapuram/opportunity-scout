# Daily Opportunity Scout — 2026-10-06

## Executive summary

The current portfolio is centered on three evidence-backed wedges:

1. **GST Exception Resolver** — strongest evidence-to-effort path.
2. **Agent Permission Diff** — promising global developer-security wedge, but narrower than the original generic AgentGuard concept.
3. **WhatsApp Stalled Deal Detector** — real revenue-leakage problem, but higher competition/platform risk.

The main strategic conclusion is that **we should validate a narrow workflow before building a broad platform**.

## A. Signals

### 1. AI-agent permission enforcement is becoming a real security problem

**Observed:** recent agent/MCP security discussions and issues show problems around excessive filesystem access, unconstrained GitHub operations, prompt injection through tool/server content, and other capability-boundary concerns.

**Inference:** "AI agent security" is a real market, but generic scanning is becoming crowded.

### 2. Indian organizations report a gap between AI policy and enforcement

**Observed:** recent industry reporting describes widespread formal AI-access policies alongside significant cases of AI accessing sensitive data beyond intended scope.

**Inference:** enforcement/observability is potentially more valuable than another policy document.

### 3. GST reconciliation remains a recurring manual workflow

**Observed:** Indian tax/accounting practitioners continue to discuss invoice-level GST reconciliation, mismatches, timing differences and client-volume problems.

**Inference:** a narrow exception-resolution tool may have a clearer payer and ROI than a generic accounting product.

### 4. WhatsApp is deeply embedded in Indian sales workflows

**Observed:** community discussions describe businesses manually monitoring WhatsApp conversations and missing follow-ups.

**Inference:** revenue-leakage detection is a better wedge than another generic WhatsApp CRM.

### 5. WhatsApp business tooling is competitive

**Observed:** existing vendors already sell WhatsApp lead/follow-up automation to Indian businesses.

**Inference:** any new product must own a very specific problem rather than compete as a general CRM.

## C. Recommended next experiment

Build a spreadsheet-first GST reconciliation prototype and test it with **3 CA firms using anonymized real data**.

### 1-day target

Deterministic matching engine:

- normalize GSTIN;
- normalize invoice numbers;
- compare taxable/tax values;
- detect duplicates;
- classify missing/mismatched records.

### 3-day target

Simple upload → reconciliation → exception report workflow.

### Success

At least 2 of 3 firms use real data and report meaningful time savings; at least one expresses willingness to pay or continue using it.

### Failure

Existing tools already solve the workflow adequately, accuracy is insufficient, or practitioners do not value another tool.

## D. Build spec

Keep V0 intentionally small:

```text
XLSX → Normalize → Deterministic reconciliation → Exceptions → Report
                                              ↘
                                           AI explanation
```

The LLM must **not** determine financial truth. It can explain exceptions already identified by deterministic code.

## E. Money logic

Potential B2B subscription is plausible because the target customer is a recurring professional workflow. Pricing must be validated rather than assumed.

## F. Kill / deprioritize

- Generic AgentGuard scanner: narrow the wedge because the category is becoming crowded.
- WhatsApp cost optimizer: insufficient differentiation for the current stage.
- Generic WhatsApp CRM: demand exists, but competition is strong.
